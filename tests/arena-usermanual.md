## Arenalytics - R package for statistical analysis and reporting

Arenalytics is an analytical dashboard developed for reporting and exploring data collected and processed with Open Foris Arena. It was designed to address one of the main challenges of sample-based assessments: generating reliable statistics, tables, and figures from large and complex survey datasets without requiring users to predefine all reporting outputs in advance. The dashboard was developed particularly for forest inventories and other sample-based assessments where users need to produce estimates such as biomass, tree density, volume, carbon stocks, or other indicators across multiple reporting domains. The dashboard allows users to dynamically analyse survey results by selecting measures, dimensions, and filters, producing estimates, totals, means, and reliability statistics on demand. 

The Arenalytics workflow begins in Open Foris Arena, where survey data are collected and processed using a calculation chain. Once the processing chain has been executed in RStudio, Arena automatically generates Minimum Area Unit (MAU) files that contain pre-computed result variables and supporting attributes required for reporting. These files are packaged into a ZIP archive and loaded into Arenalytics for analysis.

After loading a MAU zip file, Arenalytics performs automatic validation checks and provides a survey summary to help users verify that the uploaded data are ready for analysis. Users can then select an entity, choose one or more measures to analyse, and define dimensions and filters that determine how results will be aggregated and presented. Dimensions can originate from either the original survey data or from the processing chain, enabling flexible reporting across administrative units, forest types, diameter classes, species groups, and many other categories. The resulting tables are generated instantly and updated whenever the settings in the ‘Cross outputs settings’ section change.

The outcome of the Arena processing chain is a ZIP file of semi-aggregated data that will serve as input for Arenalytics, a Minimum Area Unit (MAU) file. The MAU file contains data aggregated to the Minimum Area Unit level, which is defined as the smallest homogeneous land unit in the survey area. In the Arena processing chain, the MAU is equivalent to the base unit used for statistical estimation.

Examples:
 - If a plot is completely homogeneous (single land use or vegetation type), the plot itself is the MAU.
 - If a plot is divided into several land-use or vegetation sections, then each homogeneous section becomes a separate MAU unit. Estimation variables are first computed for these sections and then aggregated to higher reporting levels.

The MAU file is automatically generated by an Arena system script as a ZIP file. It contains:
 - Result estimates for each base unit (MAU).
 - All relevant dimensions derived from categorical, taxonomic, and Boolean attributes.
 - Pre-computed measures that Arenalytics can subsequently aggregate into tables, charts, means, totals, and sampling-error estimates for any user-selected combination of dimensions.

Arenalytics reads measures at the MAU level and dynamically aggregates them to any reporting level (forest type, species, administrative region, diameter class, etc.) requested by the user. For a typical forest inventory case, where plots may be split into land-use strata or forest types, you can think of the MAU file as a dataset where each record represents one homogeneous plot section together with all its computed area-based variables and reporting dimensions.

## ArenaLytics dashboard structure

The dashboard has three pages. The Tool page holds the analysis: a sidebar with three setup steps and two result panels.

### Pages and steps

- **Home**: introduction to the dashboard, with links to the Tool and About pages.
- **Tool**: upload the data, set up the analysis and explore the results.
  - Step 1, Load ZIP file: upload and check the MAU ZIP file, then read the data.
  - Step 2, Select inputs: analysis type, entity, and base-unit and sub-unit dimensions.
  - Step 3, Configure analysis: handling of lonely primary sampling units, computation mode and confidence level.
  - Insights panel: survey summary, sampling design, entities, dimensions and measures.
  - Analysis panel: means per hectare and totals with confidence intervals, as figures and tables, with exports to PNG, CSV and a Word or HTML report.
- **About**: workflow, demo dataset, context and technical information on the package.

### Data pipeline

- `fct_checkzip()` checks that the ZIP file holds all required files;
- `fct_readzip()` reads the files and prepares the variable metadata; and
- `fct_arenalyse()` computes the design-based estimates with the srvyr and survey packages.

## Making the figure

The figure is a bar chart. It shows one bar for each class of the dimension on the x-axis, so each bar must correspond to a single estimate.

When the analysis splits the results by more than one dimension, each dimension must find a place in the figure. For example, an analysis of tree volume by forest type and tree status (dead or alive) gives one estimate for each combination of forest type and status. With forest type on the x-axis, each forest type still has two estimates, one for live trees and one for dead trees, so the figure cannot be drawn yet. There are three ways to complete it:

- **Group by** tree status: each forest type shows two bars side by side, one for live trees and one for dead trees.
- **Facet by** tree status: the figure shows two charts, one for live trees and one for dead trees.
- **Filter** tree status to live trees only, in the dimension filters: each forest type then has a single estimate, and the figure appears at once.

Until every dimension of the analysis is on the x-axis, used to group or facet, or filtered to one class, the figure card lists the dimensions to set up, and the figure download and the report are unavailable.

## Analysis options

### Lonely primary sampling units

In a stratified design, the standard error of an estimate comes from the differences between the primary sampling units (PSUs), such as clusters or plots, within each stratum. When a stratum contains only one PSU, a "lonely PSU", there is nothing to compare it with, and its contribution to the variance cannot be estimated. This happens more often when the results are split into many classes, because a stratum can then have a single PSU within a class. The estimate itself (mean or total) is not affected; only its standard error and confidence interval are.

ArenaLytics computes the estimates with the survey package for R, which offers several ways to handle lonely PSUs (option `survey.lonely.psu`, see the package help page `surveyoptions`). The dashboard offers two of them:

- **Adjust** (default, conservative): the lonely PSU is compared with the overall mean of the population instead of the mean of its own stratum, so its stratum still contributes to the variance. Standard errors tend to be slightly overestimated, and confidence intervals slightly too wide. ArenaLytics applies the same adjustment within each reporting class (option `survey.adjust.domain.lonely`).
- **Remove** (permissive): the lonely PSU is left out of the variance computation, so its stratum contributes nothing to the variance. Standard errors can be underestimated, and confidence intervals too narrow, for the classes concerned.

Adjust is the safer choice for national reporting, especially with detailed cross-tabulations. Remove can be used when strata are well populated and few lonely PSUs are expected. When in doubt, run the analysis with both options and compare the standard errors. The analysis log reports how many groups had a lonely PSU.

### Computation mode

R is fastest with vectorized operations: one instruction is applied to a whole set of values at once, instead of one value at a time.

- **Fast**: ArenaLytics estimates all the measures of the entity in a single vectorized computation. This is the quickest option, but if one measure causes an error, for example because of an unexpected value in the data, the whole computation stops and no results are returned.
- **Safe**: ArenaLytics estimates the measures one by one. This is slower, especially for entities with many measures, but an error on one measure does not stop the others. The analysis keeps the results that could be computed, and the log lists the measures that failed.

Start with Fast, and switch to Safe if the analysis stops with an error.
